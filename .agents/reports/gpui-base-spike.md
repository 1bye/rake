## Browser evidence and check boundaries

The owner's follow-up explicitly authorized real Chrome plus DevTools, while distinguishing OS IME UI. The test launches the installed Chrome binary with a separate profile under `/private/tmp/gpui-base-spike/chrome-profile`, not a mock browser or the app's embedded browser. The exact launch command and PIDs are in [followup-processes.json](/private/tmp/gpui-base-spike/logs/followup-processes.json).

The harness dispatches actual Chrome keyboard and `Input.imeSetComposition` commands, and reads **Base's own value/marked-range/focus state sampled during render**, rather than relying on the hidden HTML textarea value. For example, `n → ni → 你` produces Base marked ranges `Some(0..1) → Some(0..2) → Some(0..1)`, then commit leaves `你` and `None`; cancellation of a fresh `ni` leaves empty text and `None`. Textarea reaches `line\ntwoあ` with the composition at `Some(8..9)` before commit, then `None`. No Base Root is mounted.

Evidence: [browser harness](/private/tmp/gpui-base-spike/browser-test.mjs), [22 recorded samples and Chrome version](/private/tmp/gpui-base-spike/logs/followup-browser-results.json), [final screenshot](/private/tmp/gpui-base-spike/logs/followup-browser.png), and [Rust observation code](/private/tmp/gpui-base-spike/src/lib.rs:18).

Two harness assumptions were corrected without hiding their observations: completed-frame/focus waits remove an early navigation/focus race, and a plain HTML textarea control established that this Chrome DevTools path emits `compositionend` with `isTrusted=false` even though composition start/update are trusted. Final event assertions compare against that measured control. The control also commits `你` exactly once. [Control evidence](/private/tmp/gpui-base-spike/logs/followup-ime-control.json) and earlier failed-run evidence remain in `logs/followup-*-observation.json`. The original CUA failure is superseded for browser typing/composition by this authorized test, not retroactively recorded as a pass.

Cmd+A failure is retained separately. The corresponding Base bindings are compile-time gated: [cmd-a / ctrl-a source](/Users/yuriihulyk/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gpui-base-0.9.0/src/input/base/state.rs:279). ## Open questions

**Does Input work without Base Root?** Yes for measured rendering, typing and browser composition in this app: Input and Textarea render on native, and both edit/compose in Chrome without Root. Construction and rendering use [Input::new / Textarea::new](/private/tmp/gpui-base-spike/src/lib.rs:56); [browser entry](/private/tmp/gpui-base-spike/src/lib.rs:138) calls `single_threaded_web().run_embedded`. This is not a blanket qualification of dialogs, popovers, OS IME or accessibility. [Base Root's constructor](/Users/yuriihulyk/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gpui-base-0.9.0/src/root.rs:175) also installs a macOS accessibility hit-test forwarder, so omitting it has effects outside these input checks.

**Frame-trace replacement?** A working broader API exists, not a drop-in independent frame switch. [set_trace_enabled](/Users/yuriihulyk/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gpui-pre-0.3.11/src/profiler.rs:709) controls task and frame collection; its `bool` reports a setting change. The collector needs **`gpui/profiler`** and [returns Vec<FrameEvent>](/Users/yuriihulyk/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gpui-pre-0.3.11/src/profiler.rs:1640), whose Draw and Present cases differ. Rake currently treats every collected item as a FrameTiming, explaining seven compiler errors. The [native probe](/private/tmp/gpui-base-spike/frame-probe/src/main.rs:27) collected a real Draw event and verified trace restoration. No synthetic timing was injected. Integrating the event matching, feature forwarding and shared trace ownership into [Rake recording](/private/tmp/rake-gpui-base-phase0/crates/rake/src/inspection/recording.rs:260) remains a later migration change.

## Decisions and recommendations

1. **Approved: native Rust 1.98.** Prepared only in the throwaway toolchain and workspace manifest. The main checkout stays on 1.95, as originally protected. No nightly is required for the native alternative measured here.
2. **Approved: stable single-threaded Web.** Both worktree platform declarations disable defaults. The locked Wasm dependency graph reports no wasm_thread dependency. Retain this configuration rather than silently adopting nightly. Full Rake host builds and runtime still depend on the later API migration.
3. **Approved: DevTools composition check in real Chrome.** The browser path passes the authorized scope. OS IME candidate-window testing, other hosts, VoiceOver/NVDA, clipboard, dead keys and layout changes remain later qualification, not passing claims in this spike.
4. **Approved direction: preserve real recording using Pre's profiler.** The replacement API now has native runtime evidence. Adapt Draw/Present handling and feature forwarding in a later migration; review broader trace ownership/overhead rather than fabricating frame data.
5. **New measured condition: macOS browser Cmd+A.** Recommendation: resolve browser-aware shortcut bindings upstream or in the reviewed Rake/Base setup integration before promising macOS browser editing parity. Do not assume all other Cmd shortcuts work; only select-all was measured here. No shortcut source fix was made during Phase 0.
6. **Migration estimate and bundle budget.** The observed twenty diagnostics do not trigger the ~300 threshold, but blocked consumers remain unknown. Recommendation: reassess after compilation is unblocked and compare actual migrated Notes release artifacts before promising the final size budget. The current dev-artifact comparison does not justify requesting an editor feature split by itself.
